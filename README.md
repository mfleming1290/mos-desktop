# MOS Desktop — scoped personal workspace

One MOS-first application presented through the MOS plugin and a same-origin authenticated standalone page. Both use the same scoped backend and origin-local layout authority. Neither frontend owns native process lifetime.

Installed homelab candidate **0.2.14** includes verified layouts, Personal Home/Terminal, the compiled shared CodeMirror editor and scoped Selkies streaming. Nested folders, moves and recoverable trash/restore now pass real MOS backend and installed UI checks under the approved private single-owner Tier1 contract. Operations use existing LXC matt, admitted Home, validated paths and ordinary filesystem permissions; adversarial native-reparent race containment and MOS-wide JWT revocation are optional hardening, not claimed guarantees. Nine layout/authentication tests,37 Node tests and personal UI regressions pass. Save remains optimistic against concurrent native writers; Save As and moves never overwrite. Original terminals are preserved through separate files-only routing. Host reboot, separate-destination backup and human native/media checks remain deferred; LXC autostart stays off. Published release0.2.2 is unchanged. See [service setup and gates](backend/README.md).

For standalone use, open `/_plugins/desktop/standalone/standalone.html` on the same HTTPS MOS origin. Sign in through MOS first; the standalone page refuses to mount the desktop without a server-verified profile. It introduces no password form, token transfer, new issuer, listener or proxy route. Embedded federation still uses host Vue; the separate standalone build supplies its own Vue. Both share origin-local layout storage, including its single-writer rule; a second simultaneous presentation explicitly operates memory-only. Editor drafts are not persisted: save before closing.

Terminal typing uses a fixed25ms batching deadline rather than waiting for a typing pause. Successful input requests wake output polling immediately; active output uses75ms polls briefly, then returns to1second idle polling. Requests remain authenticated and input remains serialized without uncertain replay. This is still HTTP polling, not a continuous-stream transport.
Personal views and the bridge each share an80ms request-start budget to stay below MOS's existing20/s authentication limiter. Overload is not reported as logout; output reads back off safely and input is never automatically replayed.

## Local build

Requires Node 24.21.0/npm. Approved compiled inputs in `runtime/` are hash-pinned. No private SDK checkout, credentials or Rust compiler is required. Clock/contracts 0.1.1 are fetched into ignored cache from the already-public Clock plugin at exact commit `a06361b0d40f26bf3a66da1ebe24ea2264efbb23`, verified by SHA-256, then installed through their package interfaces. Only consumed modules enter the frontend bundle; cached archives/fixtures do not enter the plugin. Provenance is in `runtime/identity.json`; SDK source revision, package version and artifact hashes are distinct identities.

```sh
node scripts/prepare-components.mjs
cd page
npm ci --ignore-scripts --no-audit --no-fund
npm run prepare:runtime
npm run build
npm test
npm run check:built
```

Never replace published version bytes. The reviewed source allowlist excludes private SDK source, internal records, caches, fixtures and source maps. Original M0 release/runtime inputs and rollback artifacts remain unchanged. Third-party notices remain in `runtime/THIRD-PARTY-NOTICES.txt`; compiled distribution approval does not grant a public license to private SDK source. Shared Clock/contracts remain version 0.1.1 independently of the plugin version.

The MOS federation exposure is `./Plugin`, using host Vue only. The WASM URL is module-relative. One route controller serializes commands against one accepted snapshot; Vue owns only projection, focus, configuration and gesture previews. Keys are window identities, never revisions or ordering. Minimize keeps content mounted but suspends local work; restore returns to normal geometry. Closing a terminal view detaches only; explicit confirmed End terminal session is distinct.

Layout storage requires a verified scope and Web Locks. The MOS entry requests the current profile through MOS's established same-origin authenticated API and uses only the server-returned user ID; it does not decode credentials or trust stored display names/user IDs. Credential changes block pending writes, including route-exit flushes; account changes reverify and remount. Missing/denied profile or unavailable Web Locks leaves an explicit memory-only session. Scoped harness tests prove bounded intentions, single-writer ownership, restore, storage failures and account-change fencing, not actual MOS account isolation. Arrow keys on a title move it; arrow keys on its resize handle resize it. Alt+Shift+Left/Right cycles windows, M minimizes, X closes; Escape cancels pointer preview.

## Next gates and rollback

The earlier fixed-MAC start conflict was worked around by allowing LXC to assign the macvlan address. Ordinary API and installed desktop Stop/Start then passed. The host-level fixed-MAC root cause remains unproven. The renamed container keeps that network configuration; its LAN address may change, while the existing Tailscale device identity is preserved.

Publication, installation and deployment require separate approval under the current run. Local tests alone do not establish installed update behavior. Releasing a completed move or resize immediately saves its committed geometry; previews/cancelled gestures never save their uncommitted bounds. Other layout/configuration changes autosave with a short debounce. Successful writes display an increasing session count; Retry autosave appears only after a write failure. HTTP LAN addresses can run the shell using cryptographic random bytes, but missing Web Locks, profile access or browser storage reports the specific memory-only reason, not a false save. Use HTTPS or localhost for persistence; fixing startup does not make HTTP transport secure. Browser layouts are origin-local: hostname, IP, localhost and HTTPS addresses do not share a saved layout.

This is a private homelab application using temporary public Hub distribution, not a long-term public SDK project. Installed operation uses local assets without retrieving SDK source or GitHub build inputs. Making the repository private later may break anonymous discovery, updates and reinstalls even if installed assets continue working. Private/local Hub support remains unverified.

M0/M1 are accepted for the current bounded workflow; uncommon pointer/keyboard cases rely on automated supporting evidence, not exhaustive live acceptance. M2 uses a fixed authenticated GET of LXC containers with performance sampling disabled. The panel shows observation time, refreshes every 30 seconds while visible, clears observations and aborts pending reads on hide/close, and rejects late responses after credential changes. Only name, state and unprivileged flag are projected; raw config paths, credentials and metadata are not stored in layouts. Confirmed controls expose only fixed MOS POST routes for `mos-desktop/start` and `mos-desktop/stop`; no other target, operation or automatic retry is permitted. A completed request is not proof of container state: refresh observations to verify it. Closing a view never sends a stop request or reverses an admitted operation. MOS retains all authorization. The fixed link opens the existing MOS LXC administration page. No generic URL, command or shell bridge exists. M3 bounded Home/admission and M4 scoped Selkies functional integration pass; nested file mutations pass the explicitly approved Tier1 path-validation contract. Standalone authenticates through the same MOS authority. Explicit single-controller takeover with native viewer ceilings is verified.

Use MOS's normal plugin removal controls for plugin rollback. Removal must retain the separately provisioned container and persistent Home; neither is owned by frontend lifecycle. Host-side recovery copies contain private user data and stay outside public packages. Provisioning checks verified actual user namespace mapping, translated Home ownership, resource limits, restart persistence and refusal to start with Home absent. Autostart remains disabled until broader backend recovery gates pass. Authenticated bounded Home/Terminal services pass. NAS reboot and separate-destination backup acceptance remain open; do not reboot solely for testing.

Numeric version tags build through GitHub Actions and publish a complete draft-then-public release with an architecture-independent `all` Debian package, MD5/SHA-256 sidecars and tagged source archive. Main/PR builds do not publish; never replace published version bytes. MOS Hub owns discovery only.
